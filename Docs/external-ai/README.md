# 외부 Jev AI — 현재 산출물

현재 단계는 **실제 Jev API를 호출하지 않는 수동 인터페이스 검증**입니다. 별도 로컬 더미 프로그램이 Jev 형식의 요청을 받고, 터미널에서 사용자가 직접 응답합니다. 기본 provider는 `human`이며 API 키가 필요하지 않습니다.

## 바로 사용하기

```powershell
& .\tools\external-ai\Start-HumanJev.ps1
```

터미널에 현재 맥락과 질문이 표시됩니다. Choice와 단계 선택은 표시된 번호로 답하고, yes/no는 `true` 또는 `false`로 답합니다. `1`과 `0`도 yes/no의 입력으로 사용할 수 있습니다. 모든 질문에 답하면 응답을 반환합니다. `c`는 요청 취소, Ctrl+C는 종료입니다. 기한이 지난 입력은 Enter를 누르면 폐기하고 다음 요청으로 넘어갑니다.

게임 없이 시험하려면 다음 명령을 사용합니다. 연습 응답을 반환한 뒤 종료합니다.

```powershell
& .\tools\external-ai\Start-HumanJev.ps1 -Practice
```

Choice는 고른 항목만 true(1), 나머지는 false(0)입니다. yes/no(`noul`)는 true→1, false→0이고, 단계 선택(`score`)도 고른 수준의 가중치만 1입니다. 퍼센트 입력이나 소수 확률을 사용하지 않습니다. 반환한 JSON은 터미널에 표시됩니다.

더미는 `http://127.0.0.1:49173/v1/systemone`에서 `model/state/questions`를 받습니다. Choice·Noul·Score 응답 형식과 필드 이름은 [공식 계약](https://docs.typesafe.ai/api)을 따릅니다. `probabilities`는 1/0, Choice/Score의 `confidence`는 확인된 수동 답변을 나타내는 1이며 모델 추정 확률이 아닙니다. 모델은 `human-dummy`, token usage는 0으로 표시합니다.

게임 엔진이 선택을 요청하면 YgoMaster 서버가 별도 Python 앱에 전달합니다. 앱은 카드 이름, 현재 필드, 직전에 적용한 행동, 후속 선택 관계로 자연어 선택지를 만든 뒤 로컬 더미 터미널에서 사용자에게 선택을 맡깁니다. **선택지 문장은 LLM 호출 없이 생성합니다.**

앱을 재시작해도 서버가 보유한 최근 적용 이력을 받아 다음 판단에 이어 씁니다. 같은 듀얼·세대·제어 대상의 확인된 적용만 복구하며, 순서 선택은 제출한 순서를 유지합니다. 이력은 최근 64개·응답 1 MiB 이내의 일부이며 서버 자체를 재시작하면 사라집니다. 이번 패키지의 서버와 앱을 함께 사용해야 합니다.

정상 초기화한 실제 DLL과 모의 판단 앱의 왕복에 이어, 이전 브라우저 버전에서 고른 수동 판단 6건의 엔진 적용도 확인했습니다. 터미널 변경은 같은 요청·응답 계약을 사용하며, 자동 검사 19개와 실제 터미널 입력으로 확인했습니다. 실제 Jev 인증과 게임 화면에서의 입력·애니메이션 경합은 이번 수동 인터페이스 검증 범위에 포함하지 않습니다.

## 포함된 것

- 수정한 `YgoMasterClient.exe`: DLL 요청을 보류하고, 서버가 받은 결정을 엔진 스레드에서 적용합니다.
- 수정한 `YgoMaster.exe`: 별도 로컬 통신 창구와 요청·결정·적용 상태를 관리합니다.
- `JevApp/jev_app`: Python 3 표준 라이브러리만 사용하는 연결 앱과 직접 선택 더미입니다. 명시적으로 `jev` 모드를 고를 때만 연결 앱이 `JEV_API_KEY`를 읽습니다.
- 실행 스크립트, 예제 설정, 검사 재현 안내와 검증 범위 기록.

게임 DLL, 추출 카드 데이터, 기존 로더, API 키, 저장 파일은 패키지에 포함하지 않습니다. 게임과 연결할 때는 기존 YgoMaster 게임 실행 환경과 별도로 추출한 `CardData`가 필요합니다. 카드 이름/설명 외에 해당 언어의 `DLG_Indx.bytes`·`DLG_Text.bytes`·`WORD_Indx.bytes`·`WORD_Text.bytes`도 읽습니다. 연습 질문은 게임 자산 없이 실행됩니다.

## 앱과 서버 실행

패키지 또는 fork 폴더에서 PowerShell을 열고 최초 한 번 설정을 만듭니다.

```powershell
& .\tools\external-ai\Setup-ExternalAi.ps1
```

첫 번째 창에서 중계 서버를 실행합니다. 이 모드는 게임 계정·저장 데이터를 읽지 않습니다.

```powershell
& .\tools\external-ai\Start-ExternalAiBridge.ps1
```

직접 선택 더미를 먼저 실행해 두고, 다른 창에서 연결 앱을 실행합니다. 기본값은 `human`이므로 키 없이 로컬 더미에 요청합니다.

```powershell
& .\tools\external-ai\Start-JevApp.ps1 -CardData '추출한 CardData 폴더의 절대 경로' -Provider human
```

실제 Jev 호출 없이 통신을 점검하려면 마지막 명령에 `-Provider mock`을 붙입니다. 모의 앱은 첫 합법 후보만 고릅니다. 실제 Jev 실패를 숨기는 대체 판단으로 사용하지 않습니다.

`human`은 사용자 입력을 기다리며 자동 후보를 고르지 않습니다. 질문 기한을 넘기거나 터미널에서 취소하면 선택을 적용하지 않습니다. 동일한 요청 ID의 통신 재시도는 이미 받은 답변을 재사용하며, 다른 내용으로 ID를 재사용하면 거절합니다. `jev` 모드는 코드에 남아 있지만 이번 단계에서는 실행하지 않습니다.

게임 쪽 연결 설정은 기존 `ClientSettings.json`의 `ExternalAiConfigPath`에 생성된 `ExternalAi.local.json`의 **절대 경로**를 지정하는 것입니다. 수정 클라이언트와 기존 로더를 별도의 검증용 게임 실행 환경에 배치해야 합니다. 현재 작업에서는 기존 게임 설치나 Solo 캠페인에 배치하지 않았습니다. 화면에서의 경합 검증까지 남아 있으므로 본 캠페인 적용은 아직 준비 완료로 표시하지 않습니다.

외부 앱이 입력을 맡은 동안은 엔진을 기다리게 하고, 결정이 제출되면 해당 요청의 대기를 풉니다. 실제 DLL 훅을 연결한 독립 host에서 입력 창이 계속 기다리는 상황과 상충하는 입력을 재현해 확인했습니다. 게임 화면의 생성자와 실제 창 종료 동작까지 검증한 것은 아닙니다.

게임 서버와 중계를 같은 프로세스로 실행할 때는 `YgoMaster.exe --external-ai-config <설정 절대 경로>`를 사용합니다. 이미 중계 전용 서버가 같은 포트를 점유하면 함께 실행할 수 없습니다.

## 지금 처리하는 선택

메인·배틀 메뉴의 카드 명령, 드로우, 효과 확인, 페이즈 이동, 필드 배치, 필드 대상 지정, 확인 창, 해석된 단일 카드 목록을 구현했습니다. 필드 배치는 검증된 DLL의 현재 배치 조건을, 대상 지정은 공개 명령 조회의 `Decide` 비트를 사용합니다. 배치용 함수와 대상용 함수는 입력 형식이 달라서 서로 대신 호출하지 않습니다.

패 버리기는 남은 장수를 읽어 한 장씩 선택합니다. 예를 들어 “자신 패 7번째 카드 ‘Graceful Charity’: 버린다 (앞으로 버려야 할 2장 중 한 장)”을 생성합니다. 선택 후 패가 바뀌면 다음 요청의 위치와 남은 장수를 다시 읽습니다. Twin Twisters의 코스트 한 장과 대상 두 장도 실제 DLL에서 묘지 이동까지 확인했습니다.

체인에는 공개된 발동 카드, 받은 순서, 해결 상태를 담습니다. 예를 들어 상대 Graceful Charity에 대응할 때 그 카드 이름·설명과 현재 체인을 제공하고 “현재 체인에 대응할 카드나 효과를 선택한다”를 생성합니다. Magic Jammer 발동→패 코스트 한 장→상대 마법 무효화·파괴까지 실제 DLL 훅에서 확인했습니다. 카드 출처를 하나로 대조하지 못하면 출처 미확인으로 남깁니다.

Spellbook Organization의 덱 위 카드 3장 정렬도 연결했습니다. 해결 중인 체인의 카드와 실제 목록의 출처·장수·고유 번호를 확인한 뒤 가능한 순서 6개를 만들고 “덱 맨 위부터 이 순서로 놓는다”로 안내합니다. 목록 3→2→1 순서를 제출해 실제 덱 순서가 바뀌고 첫 카드가 다음 턴에 뽑히는 것까지 확인했습니다. 이 확인된 요청에만 순서 조합을 허용합니다.

YesNo는 실제 질문과 앞선 안내를 구분합니다. “Twin Twisters가 발동됐다”라는 안내 뒤에 “다른 마법·함정을 더 파괴할까?”라는 질문을 함께 제공합니다. 게임 문자열 사전과 타입이 지정된 카드 이름 치환으로 문장을 구성하며 LLM을 사용하지 않습니다.

동일한 카드도 패 순서·필드 구역·고유 번호로 구분합니다. 상대 패·덱 순서·뒷면 필드 카드 이름은 보내지 않습니다. 제외 카드와 상대 카드 목록 일부는 공개 여부가 검증되지 않아 보수적으로 숨깁니다. 현재 카드 데이터 기본 언어는 영어이며 문장 틀은 한국어입니다.

게임 문자열의 다른 치환 타입, 다중 카드 조합·소재 합계, 다른 정렬·선언 유형의 실제 듀얼 검증은 남아 있습니다. 알 수 없는 제약이나 255개를 넘는 선택지는 임의로 잘라서 판단하지 않습니다. 앱이 실패 사유를 서버에 반환하면 해당 듀얼의 외부 제어를 해제하고 기존 CPU로 복귀합니다. 이 복귀를 Jev 결정 적용으로 기록하지 않습니다.
